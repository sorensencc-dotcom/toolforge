# DRIFT-2026-07-11-005 — Fix Applied

## What Was Wrong

**Governance Claim:**
```
"Skills auto-install to toolforge library on merge to main"
```

**Reality:**
- `obsidian:ingest-wiki` exists: `C:\dev\kb-sync\modules\obsidian\ingest-wiki.sh`
- Documented: `C:\dev\kb-sync\docs\skills\obsidian-ingest-wiki.md`
- Invoked via npm: `npm run wiki:ingest:obsidian:validate`, `npm run wiki:ingest:obsidian:prompt`
- **NOT registered in manifest.json** (unlike kb-sync-nightly which IS registered)

**Gap:**
Governance didn't distinguish between:
1. **Internal KB-Sync Tools** — bash modules, invoked via `npm run`, no auto-install needed
2. **External Toolforge Skills** — registered in manifest.json, distributed via toolforge library

Claimed auto-install mechanism doesn't exist for internal tools.

---

## Root Cause

Wrote governance rule before understanding toolforge vs kb-sync distinction:
- Toolforge manifest: registered skills (like kb-sync-nightly, operator-image-build, etc.)
- KB-Sync project: internal tools (like obsidian:ingest-wiki, ingest-obsidian.sh, etc.)
- Mechanism: different paths for each type

---

## Architecture (Verified)

### KB-Sync Internal Tools

**Location:** `C:\dev\kb-sync\modules\<category>\*.sh`

**Invocation:** `npm run <script-name>` (defined in `package.json`)

**Example:**
```bash
npm run wiki:ingest:obsidian:validate
# Calls: bash modules/obsidian/ingest-wiki.sh validate
```

**Registration:** None needed. Tools are part of kb-sync project, invoked locally.

**Docs:** `C:\dev\kb-sync\docs\skills\*.md`

### Toolforge External Skills

**Location:** `C:\dev\<project>\toolforge\skills\<skill-name>\` or root skill entry in `manifest.json`

**Registration:** Entry in `manifest.json` with:
- `name`: user-facing skill name
- `runtime`: "node", "bash", etc.
- `entrypoint`: path to executable
- `owner`: creator
- `category`: classification
- `status`: active/inactive

**Example from manifest.json:**
```json
{
  "name": "kb-sync-nightly",
  "runtime": "bash",
  "entrypoint": "src/run.sh",
  "description": "Knowledge base sync with integrated cross-reference layer",
  "category": "governance"
}
```

**Auto-Install Mechanism:**
- Merge to main → manifest validated
- If skill structure + tests + docs complete → entry available in toolforge library
- External consumers can reference skill name and toolforge handles distribution

**Current:** 23 skills registered (analyze-token-burn, ashfall, kb-sync-nightly, operator-image-build, etc.)

## Corrected Governance Rule

**TIER 0 Auto-Install (Skills for Toolforge Distribution):**

Skills auto-install to toolforge library on merge to main IF:
1. ✅ Structure: skill.json + src/ + tests/ + docs/ (TypeScript/bash compatible)
2. ✅ Registration: Entry in `manifest.json` with complete metadata
3. ✅ Tests: Pass locally (`npm test` or test suite)
4. ✅ Docs: README or docs/ with usage examples
5. ✅ Caveman review: No blockers

**Example:** kb-sync-nightly (bash skill, registered, documented, tested)

---

**TIER 0 No Registration (Internal Project Tools):**

Project tools (bash modules, scripts) do NOT auto-install if:
1. Located in project `/modules/<category>/` directory
2. Invoked via `npm run` scripts (defined in `package.json`)
3. Part of larger project (not standalone skill)
4. No toolforge registration entry

**Example:** obsidian:ingest-wiki (bash module in kb-sync, invoked via npm, no toolforge entry needed)

## Lesson Learned

**Process Enhancement #1 Applied (from drift-analysis-2026-07-12-comprehensive.md):**

> For any governance document or rule:
> 1. **Map the system** — Where does this system live? What are its components?
> 2. **Verify mechanism** — Does the claimed mechanism actually exist? Can you point to code/config?
> 3. **Test assumptions** — Verify claimed auto-install actually happens
> 4. **Audit for false claims** — No statements about "automatic" behavior without code evidence

**How it worked here:**
1. ✅ Mapped kb-sync and toolforge architectures
2. ✅ Found obsidian:ingest-wiki exists (bash script)
3. ✅ Verified it's NOT in toolforge manifest
4. ✅ Found kb-sync-nightly IS registered (bash skill that auto-installs)
5. ✅ Discovered distinction: project tools vs toolforge skills
