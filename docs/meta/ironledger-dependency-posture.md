# IronLedger dependency posture

Status: reviewed alongside the Phase 2a ingestion design (`docs/meta/specs/ironledger-phase-2a-ingestion-design.md`, §4 and §14).
Scope: the runtime dependency surface added by Phase 2a file ingestion, and the standard-library choices made in its place.

## 1. Phase 0 baseline sections this note answers to

- **§2.2 Host-compromise assumptions.** Any process running as the operator, including editor extensions and language servers, can read IronLedger files. A third-party package installed into the same environment runs with the same privileges, so every added dependency widens the code that executes as the operator. Phase 2a adds one.
- **§2.4 Offline requirements.** Core accounting must function with no network. No implicit outbound calls, no telemetry, no update checks, and no dependency fetches at runtime. Build and test may fetch dependencies; the running system may not.
- **§6 Outbound HTTP(S) allowlist.** The allowlist is empty by default and centrally enforced. No dependency may open an outbound path that bypasses that guard, and no analytics, telemetry, or dependency-update host is ever allowlisted for the running system.

## 2. The single added runtime dependency

`pyproject.toml` `dependencies` gains exactly one entry:

```
ofxtools==1.1.1
```

`ofxtools` 1.1.1 is pure Python and has zero runtime dependencies of its own. `requirements.lock`, generated by `pip-compile` from `pyproject.toml`, therefore pins one line and nothing transitive:

```
ofxtools==1.1.1
    # via ironledger (pyproject.toml)
```

The plan draft suggested `ofxtools==0.9.5`. That pin was superseded: `pip install ofxtools` resolved to 1.1.1, which is the version pinned, locked, and tested.

## 3. Why `ofxtools` is acceptable

- **Parser use only, never the network client.** IronLedger calls `ofxtools`'s SGML/XML parser on local bytes and nothing else. The call site in `src/ironledger/ingest/formats/ofx.py` is `ofxtools.Parser.OFXTree().parse(BytesIO(raw))` followed by `.convert()`. IronLedger never constructs `ofxtools`'s OFX network client (`ofxtools.Client`), so the dependency adds no outbound HTTP path and nothing for the §6 egress guard to police.
- **No import-time side effects that matter to the threat model.** Importing and using the parser performs no network access and no filesystem writes. Input is a bytes buffer already read from the acquired evidence copy.
- **Build-time install only.** `ofxtools` is fetched when the environment is built or tested, never by the running system. This matches the §2.4 rule: "Build/test may fetch dependencies; the running system may not."
- **Pure Python, pinned exactly.** No compiled extension, no build step beyond a wheel install. The `==` pin plus the committed `requirements.lock` make the installed version reproducible and auditable.

## 4. What was rejected, and why

- **`click` / `typer` for the CLI.** Rejected. The Phase 2a command tree is built with the standard library's `argparse` (`src/ironledger/cli/__main__.py`). One added dependency for OFX parsing is justified because re-implementing an OFX SGML and XML parser is error-prone; a second dependency for argument handling is not, because `argparse` covers the entire Phase 2a command surface.
- **`chardet` for encoding detection.** Rejected. `src/ironledger/ingest/formats/csv_engine._decode` uses a byte-order-mark sniff plus a bounded trial of UTF-8, UTF-16, and Latin-1. The input domain is operator-supplied bank exports, which are effectively always one of those encodings, so a statistical detector adds a dependency and a probabilistic failure mode without a matching benefit.

## 5. Review trigger for a version bump

Before changing the `ofxtools` pin in `pyproject.toml`:

1. Re-confirm the "parser only, never the OFX client" property against the new version. Check that `src/ironledger/ingest/formats/ofx.py` still touches only `OFXTree().parse` and `.convert()`, and that the new version introduces no import-time network or filesystem behavior in that path.
2. Regenerate `requirements.lock` with `pip-compile` and review every line the regeneration adds or changes. A new transitive dependency is a new review item, not an automatic accept.
3. Record the outcome in the phase evidence document that carries the bump.
